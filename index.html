Sidecar Pattern

FastAPI Starter Deep Dive

This pattern offloads authorization to a dedicated container (sidecar) running within the same network namespace.

graph TD Client[External Client] -->|HTTP Request| API[FastAPI App] subgraph "Kubernetes Pod / Container Group" API -->|Auth Query| OPA[OPA Sidecar] OPA -->|Allow/Deny| API end API -->|Response| Client

How it Works

FastAPI uses an asynchronous middleware that intercepts every request. Instead of hardcoding permissions, the middleware gathers context (user, role, method, path) and sends it to OPA.

OPA Leverage

  • Isolation: If security rules change, you only update the OPA sidecar or its policy, not the API code.
  • Consistency: The same OPA sidecar can be used by disparate services in a service mesh (e.g., Istio).

Logic Sample

package rbac default allow = false allow if { input.role == "admin" } allow if { input.role == "user" input.path == ["user"] }
Co-located Pattern

Simple OPA Deep Dive

A streamlined approach where the application and OPA run on the same host, communicating via localhost.

graph LR User --> Flask[Flask API] subgraph "Shared Host / VPS" Flask -- "Localhost Query" --> OPA[OPA Binary] end

How it Works

This project uses Flask's `before_request` hook. Before any route logic executes, a synchronous HTTP call is made to a local OPA instance.

OPA Leverage

  • Low Latency: Minimal network overhead compared to remote authorization services.
  • Simplicity: Great for monolithic applications moving towards fine-grained access control.

Request Flow

# Flask Hook @app.before_request def check_auth(): # Gather Input data = { "user": request.headers.get("X-User-Id"), "role": request.headers.get("X-User-Role"), "path": request.path } # Decide if not check_opa(data): return abort(403)
Bundle Distribution

Complex OPA Deep Dive

Advanced distribution where policies are compiled into bundles and served centrally via an Nginx server.

graph TD Admin[Policy Admin] -->|Push Rego| Git[Git Repo] Git -->|CI/CD| Bndl[Bundle Server] subgraph "Regional Cluster" Node[Node.js Svc] -->|Local Decision| Agent[OPA Agent] Agent -.->|Auto-Poll| Bndl end

How it Works

OPA Agents are configured with a `config.yaml` to poll a remote endpoint every 10 seconds. Policies are served as `.tar.gz` bundles.

OPA Leverage

  • Dynamic Global Updates: Update access rules across 1000s of services in seconds without a redeploy.
  • Data Decoupling: Bundles can also contain large data sets (JSON) for context-aware decisions.

Agent Config

services: bundle-server: url: http://nginx:80 bundles: authz: service: bundle-server resource: bundles/rbac.tar.gz polling: min_delay_seconds: 10
